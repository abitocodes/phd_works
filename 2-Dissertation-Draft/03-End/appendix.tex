\chapter{Evaluation Pipeline and Reproducibility}
\label{ch:appendix-eval}

This appendix documents the open evaluation pipeline used to reproduce Chapter~\ref{ch:results} numerics, including repository layout, offline synthetic evaluation, real BigQuery extraction procedures, parameter summaries, proxy formulas, and a glossary.

\dissertationSubheading[sec:repo-layout]{Repository layout}

The evaluation pipeline lives in \texttt{A-Skill-Programs/margin\_rank/}. It ingests (1) latest ERC-20 allowances, (2) time-stamped transfers, and (3) decoded GMX \texttt{PositionDecrease} events. EndorseRank, AWP, and GF-PR scores are merged into \texttt{wallet\_rankings.parquet} via \texttt{compute\_reputation\_ranks.py}. Five proxy families are computed in \texttt{proxy\_metrics.py}; alignment and benchmarks run through \texttt{run\_dissertation\_eval.py}. Figures are produced by \texttt{generate\_dissertation\_figures.py}.

Key outputs: \texttt{data/processed/eval\_summary.json} (numerics), LaTeX fragments under \texttt{2-Dissertation-Draft/results/tables/}, and PDFs under \texttt{2-Dissertation-Draft/Figures/generated/}. Extended baselines (7-method, 6-Aave) export to \texttt{2-Dissertation-Draft/archive/extended-baselines/}.

\dissertationSubheading[sec:bq-extraction]{Real BigQuery extraction}

Requires Application Default Credentials and \texttt{GOOGLE\_CLOUD\_PROJECT}. See \texttt{docs/bigquery\_data\_plan.md} for cost guardrails.

\begin{verbatim}
export GOOGLE_CLOUD_PROJECT=your-project-id

# Phase 1 — trading-success label extraction (GMX V2) (6-month window)
python scripts/extract_margin_week.py --dry-run
python scripts/extract_margin_week.py --extract --yes
python scripts/decode_gmx_events.py
python scripts/compute_rankings.py

# Phase 2 — Reputation subgraph (monthly batches)
python scripts/extract_reputation_data.py --dry-run
python scripts/extract_reputation_data.py --extract --yes
python scripts/preprocess_arbitrum_allowances.py
python scripts/preprocess_arbitrum_transfers.py
python scripts/compute_reputation_ranks.py

# Phase 3 — Five-proxy evaluation + robustness (local)
python scripts/sample_active_wallets.py --from-parquet --extract
python scripts/run_dissertation_eval.py --real --robustness --export-latex
python scripts/generate_dissertation_figures.py
\end{verbatim}

Extraction metadata (bytes processed, row counts) is written to \texttt{data/processed/extraction\_manifest.json}.

\dissertationSubheading[sec:proxy-appendix]{Proxy operational definitions (reference)}

The following formulas match Chapter~\ref{ch:methodology} and \texttt{proxy\_metrics.py}.

\textbf{Transfer.} $\mathrm{in\_degree}(w)=|\{u:\exists u\to w\}|$; $\mathrm{in\_value}(w)=\sum_{e:u\to w}\mathrm{value}(e)$.

\textbf{Allowance.} $\mathrm{in\_approve\_degree}(w)=|\{o:\exists o\to w\}|$; $\mathrm{in\_approve\_value}(w)=\sum_o w_a(o,w)$ with $w$ as spender.

\textbf{Inverse risk.} $\mathrm{loss\_avoidance}(w)=-\sum_c\min(\mathrm{PnL}_c,0)$; $\mathrm{non\_loss\_close\_rate}(w)=1-|\{c:\mathrm{PnL}_c<0\land\neg\mathrm{liq}_c\}|/|\mathcal{C}(w)|$; $\mathrm{worst\_close\_pnl\_score}(w)=-\min_c\mathrm{PnL}_c$.

\textbf{Sybil-adjusted stability.} $\mathrm{inbound\_counterparty\_ratio}(w)=|\{u:u\to w\}|/|T^{\mathrm{in}}(w)|$ (self-transfers excluded); tenure in days; active months.

\textbf{Trading success.} $\mathrm{close\_success\_count}(w)=|\{c:\mathrm{PnL}_c>0\land\neg\mathrm{liq}_c\}|$; $\mathrm{realized\_gain\_proxy}(w)=\sum_c\max(\mathrm{PnL}_c,0)$; $\mathrm{close\_success\_rate}(w)=\mathrm{close\_success\_count}(w)/|\mathcal{C}(w)|$.

\dissertationSubheading[sec:glossary]{Glossary}

\begin{description}
\item[Allowance] ERC-20 authorization for a spender to transfer tokens on behalf of an owner.
\item[Alignment] Rank agreement between reputation scores and a validation proxy ($\rho$, $\tau$).
\item[Construct overlap] Shared data source between a ranking method and a proxy, inflating alignment.
\item[Endorsement graph] Directed graph of latest allowances (EndorseRank input).
\item[Matched cohort] Primary sample of $n=5{,}521$ wallets meeting eligibility rules.
\item[Expanded wallet pool] Larger address set ($N=31{,}612$) for runtime scaling.
\item[PageRank] Spectral ranking by stationary distribution of a damped random walk.
\item[Proxy] Observable wallet metric used for domain-intuition validation.
\item[Teleport] Uniform jump in PageRank with probability $1-d$.
\end{description}
