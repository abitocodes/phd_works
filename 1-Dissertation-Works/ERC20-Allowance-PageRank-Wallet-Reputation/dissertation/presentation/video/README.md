# 유튜브 해설 영상 (한국어판, 영문판)

발표 슬라이드(59장, 클릭 단계 304개)를 가로 1920×1080, 30fps의 긴 해설 영상으로 만드는 도구예요. 화면은 슬라이드 그 자체이고, 슬라이드의 움직임을 프레임 단위로 그대로 찍은 위에 내레이션, 배경 음악, 모션 그래픽을 얹어요. 한국어판과 영문판이 따로 나와요(각 약 2시간 10분).

| 결과물 | 내용 |
|---|---|
| `thesis-explained-ko.mp4`, `thesis-explained-en.mp4` | 1080p30 H.264, AAC 192k, 약 −15 LUFS |
| `thesis-explained-<lang>.srt` | 자막(목소리에 맞춘 시각). 유튜브에 자막 파일로 올려요 |
| `thesis-explained-<lang>-chapters.txt` | 유튜브 설명란에 붙이는 챕터 목록(0:00부터) |

## 만드는 순서

```bash
bash build_video.sh ko WORKDIR      # 또는 en. WORKDIR에 중간 파일과 결과물이 생겨요
```

1. `extract.mjs` — 클릭 단계마다 발표 노트, 보이는 요소의 무대 좌표(앵커), 참고 화면을 뽑아요.
2. 대본 — `scripts/<lang>/u01.json … u20.json`. 단계마다 줄 단위로 `sub`(자막 글), `tts`(읽을 글: 한국어는 한글만, 영어는 숫자 없이), `focus`(가리킬 앵커), `zoom`, `mark`, `card`(용어 카드)가 있어요. 발표 노트를 기준으로 쓰고, 노트에 없는 숫자나 주장은 넣지 않았어요. 수정 분석의 판정은 늘 '재분석', 사후 비교는 '사후'로 말해요.
3. `tts.py` — Supertonic 2(Supertone, OpenRAIL-M, 목소리 F3)로 줄마다 읽고, Whisper로 다시 들어 글자 오류율이 0.2를 넘으면 다시 읽어요. 속도는 한국어 1.22, 영어 1.15예요.
4. `music.py` — 배경 음악을 코드로 지어요(네 악장, 70 BPM). 외부 음원을 쓰지 않아서 저작권 문제가 없어요. 장마다 악장이 바뀌어요.
5. `plan.py` — 대본, 말 길이, 앵커 좌표를 묶어 그리기 계획을 만들어요. 여는 카드와 닫는 카드의 제목 줄바꿈도 여기서 정해요.
6. `render.mjs` — 크로미움에서 덱을 가상 시계(`vtime.js`)로 돌려 장마다 한 조각씩 그려요. `overlay.js`가 카메라 확대, 선이 그려지는 강조 테두리, 밑줄, 스포트라이트, 용어 카드, 여는 카드와 닫는 카드를 그려요. 움직임이 없는 프레임은 앞 프레임을 다시 써서 빨라요.
7. `mix.py` — 목소리를 기록된 프레임에 놓고, 음악을 목소리 밑으로 낮춰(말할 때 약 −34 LUFS, 쉴 때 −27) 섞은 뒤 MP4, 자막, 챕터 목록을 만들어요.

## 필요한 것

- Node.js와 `../tools`의 `playwright-core`(`npm install`), 미리 깔린 크로미움(`tools/shoot.mjs`와 같아요)
- ffmpeg
- Python 3.10 이상: numpy, scipy, soundfile, pyloudnorm, onnxruntime, faster-whisper
- 처음 한 번 Hugging Face에서 Supertonic 2와 Whisper 모델을 받아요

## 알아 둘 것

- 카메라는 덱의 움직임이 끝난 뒤에만 움직이고, 다음 클릭 전에 전체 화면으로 돌아와요. 덱이 요소 위치를 재는 동안 화면이 확대돼 있지 않게 하려는 거예요.
- 3D 장면(`s03-06`처럼 계속 도는 장면)은 프레임마다 찍어서 그리는 데 오래 걸려요.
- 원래 슬라이드는 끌어서 돌리거나 손잡이를 움직일 수 있지만, 영상에서는 그렇게 할 수 없다고 대본에서 밝혀요.
